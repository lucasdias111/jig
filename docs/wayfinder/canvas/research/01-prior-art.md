# Prior art: how agents draw on canvases

Research for [Prior art: how agents draw on canvases](../01-prior-art-agents-drawing.md). Feeds [The block catalogue](../03-block-catalogue.md) and [The agent's drawing protocol](../06-drawing-protocol.md). Researched November 2026; dates are the sources' own, and where a page gave none it says so. Secondhand claims are marked.

## Takeaways for Jig

**For the block catalogue**

1. **Typed, inert data is where the field has landed.** Eraser open-sourced its diagram format (Sept 2026) as schema-validated JSON that "cannot compute", with strong defaults so a short snippet renders well. Cursor's canvases (Apr 2026) are built from first-party components (tables, boxes, diagrams, charts, diffs, todos). tldraw's agent creates shapes in a simplified typed format that Jig-like code converts and sanitises. The free-code route (Figma's `use_figma` runs Plugin API JavaScript; artifacts are whole HTML/React files) needs a mandatory skill before every call and gives the look away. This backs Jig's settled choice of a typed catalogue.
2. **The diagram kinds everyone converges on** are flowchart, sequence, state, ER/data model and architecture (regions holding components). Mermaid's set is the de facto list: Excalidraw, tldraw, FigJam and Miro all import it, and each converts only that core into native editable shapes and falls back to an image for the rest. Jig's code-flow, flow-change, data-model and region blocks cover this core; sequence and state are the gaps worth deciding on.
3. **Changes above the diff are shown as layers with a diagram per layer, chosen by what changed.** CodeRabbit (June 2026) splits a PR into dependency-ordered cohorts (schema, logic, call sites, front end, tests), each with a summary and, only where useful, a sequence diagram for a new call flow, a state machine for a lifecycle change, an ERD for a data-model change. Devin Review groups related hunks, orders them to read top to bottom, explains each, and detects moved code instead of showing delete-plus-add. That suggests Jig's flow change, data-model change and pseudo-code change are views of one change, ordered, with the real diff as the bottom layer.
4. **Review the shape before the code.** Figma's FigJam-for-agents post (Apr 2026) reports the plan diagram, reviewed first, made the PR "an easy merge". Supports blocks → implementation with a review step at the block level, not only per edit.
5. **Comments, not shapes, for remarks.** tldraw (Aug 2026) moved agent feedback onto anchored, threaded, resolvable comments because agent-drawn notes are anonymous and pile up. Jig's `map_note` and the user's suggestions should be records attached to a block, kept apart from content blocks.

**For the drawing protocol**

6. **Model picks structure, engine picks geometry, with optional hints.** Mermaid, D2 (dagre/ELK), Eraser's old DiagramGPT and FigJam's `generate_diagram` all let a layout engine own coordinates. The 2026 shift: Eraser now lets the model write coordinates, and D2's TALA honours locked positions and `near` while routing the rest. tldraw's team says plainly that agents are very bad at 2D and needed align/distribute/stack actions and rounded, origin-relative numbers. For Jig: blocks carry relative placement hints (near, beside, inside, before/after in a flow), Jig lays out, and nothing requires the model to write pixels.
7. **Stable ids plus a declarative diff beats imperative edits and string patches.** Miro's current server (Oct 2026) replaced its per-kind diagram and layout tools with `canvas_update_from_svg`: send the scene, matched to the board by `data-miro-id`, and only the changes are applied. tldraw keys every action by shape id and repairs bad ids. Artifacts' `old_str`/`new_str` patches are fragile (exact unique match; secondhand report of silent no-ops). For Jig: one "show/patch scene" call keyed by agent-chosen ids that Jig diffs, with deletes explicit.
8. **Read-back in tiers, as structure plus (optionally) a picture.** tldraw sends focused shapes in full, shapes in view as id/type/bounds/text, and shapes off-screen as clusters with counts, plus selection, the user's recent actions, and lints. Figma's `get_figjam` returns an XML outline with screenshots. Both say structure and image together beat either alone. Jig's blocks are typed, so the outline carries most of it; tiers keep it compact on large boards, and the user's recent edits must be in it.
9. **Teach the format with a tool, validate with errors.** Excalidraw's MCP has `read_me` before `create_view`; Miro has `canvas_get_canvas_composer_skill` and per-format skill loads; Figma's skills are mandatory. Mermaid pipelines use the real parser as validator and feed errors back, about three retries. Jig already returns unknown places from `lens::resolve` as tool errors with near names; extend that to every block field.
10. **Stream per block.** tldraw applies each action once it has finished streaming and ignores partial ones; Excalidraw's MCP streams elements in one by one with a draw-on animation. Per-block granularity is the norm.
11. **Edit one part, keep the rest; know what the user changed.** Miro's data: 57% of calls (Aug 2026) were agents reading a board and acting on it, and it names iterating on a part rather than regenerating as what makes a collaborator. tldraw sends recent user actions. No tool found marks per-element ownership; that is Jig's own question ([Ownership and suggesting](../05-ownership-and-suggesting.md)).
12. **Opaque content must be handed back as source.** Make Real (Nov 2023) found the model couldn't see its own iframe in an export, so it sends the previous HTML with the annotated screenshot. Any Jig block that renders something rich (a diff, a summoned view) needs its data in the read-back, not just its box.

## tldraw

- **Agent starter kit** (https://tldraw.dev/starter-kits/agent, template README https://github.com/tldraw/tldraw/blob/main/templates/agent/README.md). Emits: streamed typed actions, each a Zod schema with `_type` first; per-action util with `applyAction`, `sanitizeAction`, `getInfo`. Capabilities: create/update/delete shapes, pen strokes, rotate/resize/align/distribute/stack/reorder, think, message, todo list, move viewport, count shapes, schedule follow-ups and reviews. Modes (`working`, `reviewing`) scope which actions and prompt parts apply; the system prompt is rebuilt each step of an agentic loop.
  - Placement: model writes positions, offset from where the chat started and rounded; multi-shape layout actions do the hard part.
  - Read-back: screenshot of the agent's viewport, BlurryShape (in view: id, type, bounds, text), FocusedShape (full properties, also the creation format), PeripheralShapeCluster (off-screen: bounds and count), selection, context items the user adds, recent user actions, lints of likely problems, history.
  - Incremental: actions by shape id, applied as each completes streaming; sanitiser fixes missing ids and makes new ones unique.
  - Changes shown: each action is a row in the chat history with icon and description, collapsible with a summary.
- **AI overview** (https://tldraw.dev/docs/ai, edited Jan 2026): canvas as output (embeds, custom preview shapes), workflows (nodes with ports), agents, driving the editor. Lessons stated: send image and structured data; sanitise model output.
- **Mermaid import** (https://tldraw.dev/docs/mermaid, Apr 2026): `@tldraw/mermaid` turns flowchart, sequence, state and mindmap into native, editable shapes in one group; others via a fallback SVG.
- **Make Real** (https://tldraw.dev/blog/make-real-the-story-so-far, Nov 2023): select a drawing, image to GPT-4V, single HTML file back in an iframe shape. Iterate by drawing annotations on the result; the previous HTML is sent too because exports show iframes blank.
- **Fairies** (Dec 2025 experiment, fairies.tldraw.com; talk summaries https://www.sean-weldon.com/blog/2026-09-11-the-spatial-harness-bringing-agents-to-the-canvas-max-drake-tldraw, secondhand): several agents on one canvas, an orchestrator with a visible todo list, each agent's state shown. Talk lessons: screenshot plus JSON needed together; models are weak at 2D and need a harness; viewport moves act like code search.
- **Agents can't point** (https://tldraw.dev/blog/agents-cant-point, Aug 2026): agent feedback as anchored comment threads (`@tldraw/commenting`, SDK 5.3) rather than shapes; attributable, resolvable, removable.

## Excalidraw

- **Text to diagram** (2023-24; library https://github.com/excalidraw/mermaid-to-excalidraw): the model writes Mermaid; the library converts it to Excalidraw elements. Native for flowchart, sequence, class, ER, state, Gantt, quadrant, timeline; others become an image. v3 lays out itself (no Mermaid DOM render), so diagrams look different from Mermaid's.
- **Official MCP app** (https://github.com/excalidraw/excalidraw-mcp, 2026, undated): remote server, `read_me` (format reference) then `create_view`; streams elements as hand-drawn SVG with camera control, then fullscreen editing. Tool list and checkpoint tools seen only in listings (secondhand). Community servers (e.g. yctimlin/mcp_excalidraw) expose ~26 element-level tools: create/update/delete/query with explicit coordinates, align, distribute, group.
- Incremental edits and user edits: not documented by the official app; the community servers re-query elements.

## Figma / FigJam

- **FigJam as the coding agent's whiteboard** (https://www.figma.com/blog/figjam-your-coding-agents-whiteboard/, Apr 2026): agent researches code, drafts a plan, draws it in FigJam for team review, reads it back with `get_figjam`, implements; the PR links the board.
- **MCP tools** (https://developers.figma.com/docs/figma-mcp-server/tools-and-prompts, undated): `generate_diagram` takes a description or Mermaid (flowchart, Gantt, state, sequence, architecture, ER) and Figma lays it out; `use_figma` runs Plugin API JavaScript to create, edit or delete anything (https://developers.figma.com/docs/figma-mcp-server/write-to-canvas; needs the `figma-use` skill, 20 KB output cap, advises small steps); `get_figjam` returns an XML outline plus screenshots; `get_metadata` an XML outline with ids, types, positions, sizes.
- Takeaway: two tiers, a declarative DSL for diagrams and an escape hatch of real code for everything else, read back as XML plus pictures.

## Miro

- **MCP server** (public beta Feb 2026; tools https://developers.miro.com/docs/miro-mcp-tools, updated Oct 28 2026). The earlier `diagram_create` (a Miro DSL for flowchart, UML class, sequence, ERD, fetched first with `diagram_get_dsl`), `layout_*` and `context_*` tools were removed. Now: `canvas_create_from_svg`, `canvas_update_from_svg` (diffs an SVG against the board by `data-miro-id`, applies only changes), `canvas_read_as_svg`, `canvas_search`, a composer skill and per-format skills; diagrams are Mermaid inside the SVG. Typed formats (table, timeline, kanban, doc, diagram, prototype) via `board_create_format`; comments have their own tools.
- **Usage** (https://miro.com/blog/miro-mcp-server/, Oct 2026): 57% of August calls were agents reading a board and acting on it; about three in four users are outside engineering; editing one part instead of regenerating is called out as what makes it collaborative.
- Takeaway: Miro moved from many per-kind tools to one scene format with a server-side diff keyed by stable ids.

## Eraser

- **DiagramGPT** (archived, https://www.eraser.io/archived/diagramgpt-32k): GPT-4 classified the diagram type, then wrote Eraser's diagram-as-code; layout by engine. Edits by prompt, by editing the DSL, or by dragging (https://www.eraser.io/ai/plantuml-editor). Docs (https://docs.eraser.io/docs/ai-diagrams, undated) list sequence, ERD, cloud architecture, flowchart.
- **Eraser Diagrams, open-sourced** (https://www.eraser.io/blog/open-sourcing-eraser-diagrams, Sept 7 2026): JSON of `entities` (with x/y and `containerId` nesting) and `connections`; principles: easy to bootstrap (defaults), customisable, inert by default (schema-validated, no computation, icons sanitised). Argues frontier models since late 2025 can lay out by coordinates, and that engines that minimise crossings lose geography and can't honour "fit this on a slide". Rejects SVG/HTML (too low), draw.io XML (verbose), D2/PlantUML/Graphviz (engine owns layout). No word on incremental edits.

## Mermaid and D2 as agent output

- **Mermaid** is the lingua franca: rendered in GitHub, Claude, CodeRabbit; imported natively by Excalidraw, tldraw, FigJam, Miro. Known weakness: syntax errors. Common fix is the real parser as validator, errors fed back, about three retries (GenAIScript's repairer, https://microsoft.github.io/genaiscript/blog/mermaids; a NeurIPS 2026 paper on verifier-guided repair for evolving diagram DSLs, https://neurips.cc/virtual/2026/173008). Layout is the engine's, and re-layout after a small edit can move everything.
- **D2** (https://d2lang.com/tour/layouts/, undated): dagre (default) and ELK own all positions; TALA, built for software architecture, honours locked `top`/`left`, `near` to objects and per-container direction. Third-party reports say TALA went open source in Sept 2026 and that one added node can reshuffle its layout (secondhand, unverified).

## Artifact-style views

- **Claude artifacts**: whole documents (HTML, React, SVG, Mermaid, Markdown) shown beside the chat, versioned per update. Edits reportedly go through an `update` with `old_str`/`new_str` exact-unique replacement (secondhand, https://bramcohen.com/p/how-claude-web-is-broken), like the API's documented `str_replace` (https://platform.claude.com/docs/en/agents-and-tools/tool-use/text-editor-tool). No canvas read-back; the model re-reads its own text.
- **Cursor canvases** (https://cursor.com/changelog/04-15-26, Apr 15 2026; Design Mode and prompt buttons in 3.7, June 2026; cloud agents and shared links Oct 2026, per secondary summaries): agent-built dashboards and interfaces from first-party components, including Cursor's diff and todo components, kept as durable artifacts in a side panel. Format and update mechanism not documented on the changelog.
- **v0** (https://vercel.com/blog/v0-composite-model-family, 2025): a frontier model generates, a fast Quick Edit model takes narrow edits, a fixer repairs errors while streaming; a diff view reviews changes (https://vercel.com/changelog/v0-now-includes-diff-view-to-review-code-changes). Output is real code, not a scene.
- Takeaway: artifacts trade structure for reach; patching them is text surgery, which is the fragility Jig's typed blocks avoid.

## Showing code changes above the line diff

- **CodeRabbit Review / Change Stack** (https://coderabbit.ai/blog/coderabbit-review-reads-a-pr-how-author-would-explain-it, June 2026; https://docs.coderabbit.ai/pr-reviews/walkthroughs): builds a syntactic and semantic graph of the change first and renders that, rather than asking a model to explain a diff; cohorts of related blocks ordered by dependency; per-cohort summaries grounded in the PR and issues; diagrams only where they help (sequence for new call flows, state machine for lifecycle, ERD for data model); moved code isn't shown as churn; wrong cohorts would be worse than a flat diff, so cohorts form only when relations are clear.
- **Devin Review** (https://cognition.com/blog/devin-review, undated; docs https://docs.devin.ai/work-with-devin/devin-review): groups logically connected hunks, orders them to read top to bottom, explains each, detects copies and moves, flags issues by severity, inline chat.
- **Ink & Switch, Patchwork notebook** (https://www.inkandswitch.com/patchwork/notebook/2024-version-control/, 2024): for prose, an overview of changes is hard with either line diffs or tracked changes; they tried summary diffs, a minibar of where changes are, hover to show deletions, and authorship in diffs; diff views vary far more by document type than history does (detail pages fetched only partly).
- **FigJam for agents** (above): review the architecture diagram before the code.
- Common thread: show the change at the level of the thing it changes (calls, states, schema), ordered by dependency, with the line diff as the last layer and moves not counted as change.
